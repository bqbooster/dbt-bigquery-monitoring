## dbt-bigquery-monitoring v0.27.0 - November 15, 2026

### Features


  - Declare compatibility with dbt v2 (Fusion) while keeping dbt Core 1.3 and newer (`require-dbt-version` is >=1.3.0,<3.0.0)

  - Refresh INFORMATION_SCHEMA models from current BigQuery docs, including property graphs, reservation failover history, and new jobs, columns, and reservation timeline fields

  - Add initial_backfill_days, defaulting to 166 so project-mode first loads and incremental catch-up stay on the previous window unless you set the variable

  - Add optional edition-aware slot pricing. It is off by default, so flat_pricing_query_cost still multiplies by hourly_slot_price (0.04 unless that variable is already overridden). Set use_edition_slot_pricing to price STANDARD, ENTERPRISE, and ENTERPRISE_PLUS. Null and unknown editions keep hourly_slot_price. No schema change and no full refresh is required; previously written incremental costs stay until those partitions are rebuilt

  - Behavior change for repeated-query grouping. jobs_costs_incremental, most_repeated_jobs, and materialization_candidates now group by query_info.query_hashes.normalized_literals, falling back to the raw query text when the hash is null. Column names and types are unchanged. query is one example statement, and query_fingerprint plus normalized_query_hash stay extra columns. most_repeated_jobs sums each hour once instead of repeating hourly totals once per job. Clustering stays hour plus query. After upgrading, existing users must full-refresh so older hour partitions use the new grain. dbt run -s jobs_costs_incremental most_repeated_jobs materialization_candidates --full-refresh. Skipping that leaves old hours grouped by raw query text and new hours grouped by fingerprint. Audit-log-only mode has no query_info and keeps the query text

  - Append creation-to-start queue wait and p50/p90/p99 duration percentiles on the compute rollups. Existing columns and median_duration_seconds are unchanged. Minute percentiles use APPROX_QUANTILES on the jobs that model already reads; a null start_time stays null, and SAFE_OFFSET returns null when every queue wait in the minute is null. The hour model still reads every minute row and does not scan JOBS again. Its new percentile columns are query-count-weighted averages of the minute values. on_schema_change is append_new_columns and clustering is unchanged, so the upgrade does not require a full refresh. Minute partitions that this run does not rewrite keep nulls in the new columns until they are rebuilt

  - Add incremental job_performance_insights and job_performance_insights_per_hour for slot contention, insufficient shuffle quota, partition skew, high-cardinality joins, and shuffle spill. Existing models are unchanged. jobs_done_incremental_hourly() with no arguments is still SELECT * with the same filters. The new models use on_schema_change append_new_columns. Null or empty performance insights are false flags and zero counts. Null or empty job_stages (including row-level security) store NULL shuffle bytes, not zero. Audit-log-only mode does not reference those structs. Region and project mode both read jobs_with_cost

  - Behavior change for client_type. jobs_with_cost now classifies Elementary, Airflow, Dataform, Hex, BI tools, orchestrators, user agents, and service accounts by default. The column name and type are unchanged, but values may differ for rows recomputed going forward (a dbt user agent is dbt, not dbt run). NULL labels, NULL user agents, and blank user agents stay Unknown. A non-empty user agent that matches nothing is kept as the label. jobs_with_cost is a view and picks this up on the next run. Full-refresh compute_rollup_per_minute and compute_rollup_per_hour to reclassify historical partitions. Incremental runs succeed without a full refresh and only rewrite recent partitions. dbt stays ahead of Airflow when both labels are present, and a key named model is not classified as Mode

### Fixes


  - Run the INFORMATION_SCHEMA.PARTITIONS table create outside the joined script so a dataset with tables no longer fails with Unexpected ";"

  - Discover datasets from each input_gcp_projects entry so dataset-scoped INFORMATION_SCHEMA models query those projects instead of the execution project

  - Materialize project configuration INFORMATION_SCHEMA models with the package materialization (views in region mode, per-project tables in project mode) and document bigquery.config.get, bigquery.config.update, and bigquery.datasets.listSharedDatasetUsage. Organization configuration models stay enabled views

  - Stop compute_rollup_per_hour from multiplying sums when job and statement type arrays are unnested. unique_users and unique_sessions now count distinct values across the hour once compute_rollup_per_minute has user_emails and session_ids. Those two columns are appended (on_schema_change=append_new_columns), so existing incremental tables do not need a full refresh to keep building. A full refresh of the minute model, then the hour model, corrects historical sums and distinct counts. Until then, hours whose minute rows still have NULL id arrays keep the sum of the per-minute distinct counts. Output column names and types of compute_rollup_per_hour are unchanged. No downstream model refs it. Incremental runs still rewrite only partitions at or after the max hour partition; a full refresh rewrites every partition.


  - Limit jobs_with_cost to lookback_window_days so the jobs scan is pruned to about one extra day of partitions. Views that read it directly now cover only that window; raise lookback_window_days for longer history. Incremental models cannot catch up a gap longer than the lookback. No full refresh is required.

  - Add new INFORMATION_SCHEMA columns on existing project-mode tables without --full-refresh, replace leftover configuration views with tables, keep organization configuration models enabled, leave preview failover history disabled, and continue dataset discovery when one input project cannot be listed without writing a table

### Docs


  - Document how to disable information_schema_jobs_by_project with a root-project boolean. The model stays enabled, so existing refs keep working in region and project mode

  - Document that total_services_sku_slot_ms is null unless a job has SERVICES_SKU external service costs, and that keeping the column costs essentially nothing. Omit it with enable_total_services_sku_slot_ms set to false or DBT_BQ_MONITORING_ENABLE_TOTAL_SERVICES_SKU_SLOT_MS=false. The column stays selected by default. When that variable is unset, enable_experimental_fields still controls it.

### Dependencies


  - Pin Fusion CI to 2.0.11 (with a weekly job on the latest stable release) and bump CI to Python 3.15, uv 0.13.7, dbt-bigquery 1.12.2, SQLFluff 4.5.0, and current GitHub Actions majors
